# Maestro — план разработки

> **Статус:** v0.1 от 2026-10-04, на ревью. Опирается на функциональный план [`plan.md`](plan.md) v0.5, исследования [`research/`](research/) и таблицы паритета [`research/parity-lore.md`](research/parity-lore.md), [`research/parity-preset.md`](research/parity-preset.md).
>
> **Как комментировать:** как и в плане — строкой `> текст` под нужным пунктом.
>
> Здесь — **как и в каком порядке** строится Maestro: устройство кода, стенд и тесты, задачи по этапам, выпуски и выкладка. Что делает каждый модуль — в `plan.md`, сюда это не повторяется.

---

## 0. Процесс

1. **Этапы — строго по порядку** (§3). Каждый этап начинается после твоего явного «го».
2. **Внутри этапа** — задачи по порядку; на развилках, не решённых планом, — вопрос тебе.
3. **В конце этапа:**
   - отчёт `docs/reports/stage-N.md` на русском: критерии приёмки, результат, как проверено (по образцу отчётов NAI Studio);
   - автопроверки на стенде зелёные;
   - ты смотришь и одобряешь;
   - тег `stage-N`.
4. **Выпуски** (R1 после этапа 1, R2 после этапа 3, R3 после этапа 4, дальше — каждый этап): повышение версии, `CHANGELOG.md` на русском, собранный `dist/` в репозитории (ST ставит расширения из git). Каждая выкладка на сервер — только с твоего разрешения (§5).
5. **Коммиты** — от твоего имени, без подписи ИИ; сообщения на английском, короткие. Пушить — когда скажешь.
6. **Публичность:** в репозитории нет деталей сервера и личных примеров; `docs/review/` в git не попадает.

## 1. Устройство кода

### 1.1 Инструменты
Как в NAI Studio:
- TypeScript (strict), сборка Vite в один ES-модуль `dist/index.js` + `dist/style.css`;
- тесты Vitest (+ happy-dom для интерфейса), ESLint, Prettier;
- `npm run check` = типы + линтер + тесты; `npm run build`; `npm run deploy:local` — на стенд.

`manifest.json`:
- `loading_order` выше 100 (после Qvink, CK и NAI Studio — перехватчик Maestro последний);
- `generate_interceptor`;
- хуки `activate`, `enable`, `disable`, `delete`, `clean`;
- i18n `ru-ru` и `en-us`;
- `minimum_client_version: 1.19.0`.

### 1.2 Папки
| Папка | Что там | Правило |
|---|---|---|
| `src/index.ts` | вход, хуки жизненного цикла | — |
| `src/host/` | всё общение с ST: типизированный контекст, события с управлением порядком (первым / последним / после соседа), **динамический импорт модулей ST по URL** (world-info, script, openai, preset-manager, chats, regex) с проверкой возможностей, перехват `fetch` (страж вкладок и учёт стоимости), подмена обработчиков кнопок | единственное место, где известны внутренности ST |

### 1.3 Ключевые технические решения
Подтверждены перепроверкой (отчёт `review/audit-v0.4.md`, раздел 2):
- **Лор на лету:** обработчики загрузки записей и шагов сканирования; правки — на копиях, новыми значениями, детерминированно; переопределения канона — подменой на месте.
- **Тексты только для сканирования:** вставка без позиции с флагом сканирования, ставится в перехватчике и стирается после генерации.
- **Сценарии генерации:** замена сообщений последним обработчиком сборки промпта (правкой того же списка) + параметры запроса в событии готовности настроек; режим потока не трогается.
- **Условные блоки:** `{{if .maestro_<флаг>}}…{{/if}}` в пресете + одноразовые локальные флаги чата. Требует нового движка макросов ST (проверяется мастером). Запасной вариант без записи в чат — предобработчик движка макросов на время генерации (решим на этапе 8, после проверки настроек сервера).
- **Показ тегов:** обработчик форматирования сообщений (после регексов), не регекс-скрипт.
- **Кнопка лорбуков:** подмена экспортированного обработчика ST; перехват Lore Library DES снимается обратимо.
- **Раздел пресетов:** скрытие раздела Prompt Manager и кнопка студии на его месте; сохранение пресета — только с явным содержимым.
- **Страж вкладок и стоимость:** один перехват `fetch` при загрузке, никогда не снимается во время генерации.
- **Фоновые запросы:** `sendRequest` профиля подключения; у ассистента — свой цикл с инструментами.
- **Сохранение лорбуков:** своя очередь сохранения по книгам (общий таймер ST теряет записи), после записи — обновление штатного редактора и сброс кэша DES; книги включаются и выключаются через обработчик ST, не прямой правкой списка (`parity-lore.md`, трудные места).

### 1.4 Код соседей
- DES-RU и Lorebook Localizer — наши: нужные доработки (plan §16) делаются в их репозиториях отдельными коммитами и выпусками, в своём этапе.
- Чистые помощники DES-RU (склонения, регулярки имён, разбор BunnyMo) — AGPL, совместимо: подключаются через API DES-RU (§16), а не копированием, чтобы не было двух версий.
- NAI Studio — наш: доработки этапа 3 (паспорта уровня чата, API, события, непрерывность по id места) — отдельным выпуском NAI Studio до выпуска R2.

## 2. Стенд и тестирование

### 2.1 Стенд
- Локальный ST 1.19.0 в docker (`st-local-docker`, порт 8010).
- Соседи закреплены по версиям: DES 2.6.0, CarrotKernel 1.0.0, BunnyMo V3.0 с паками, Qvink 1.3.29, NAI Studio (текущая), DES-RU 0.7.0, Lorebook Localizer 0.1.0.
- Основная модель — **имитация** (OpenAI-совместимый сервер в `tools/mock-llm`), подключённая как Custom Chat Completion.
- Пресет — Marinara v10 (публичный) с нейтральными правками, похожими на твои.
- Скрипт `tools/stand` поднимает стенд с нуля: копирует закреплённые версии, конфиг, фикстуры.

### 2.2 Имитация модели
Сценарии по ключевым словам в последнем сообщении:
- обычный ответ с JSON-блоком DES в начале;
- ответ без JSON;
- уход в английский;
- ответ за {{user}};
- отказ и морализаторство;
- обрезанный ответ;
- служебный мусор (`<｜begin▁of▁sentence｜>`, код);
- лист `!fullsheet` с хвостом сцены и трекером;
- ответы по JSON-схеме для фоновых задач Maestro (ревизия, живой канон, закулисье);
- вызовы инструментов для ассистента.

Каждый ответ несёт `usage` со стоимостью, как OpenRouter. Задержки и ошибки (429, 500, обрыв потока) включаются флагами.

### 2.3 Фикстуры
- **Эталонный длинный чат** — синтетический (без твоих материалов), 300+ ходов с данными DES и Qvink.
- **Большая книга мира** с глубокой рекурсией — по форме как реальная проблемная (49 записей, цепочки), но с выдуманным содержанием.
- Паки BunnyMo (публичные), архив CK с несколькими персонажами, в том числе с кириллическими именами.

### 2.4 Уровни тестов
| Уровень | Что проверяет | Где |
|---|---|---|
| Unit | вся чистая логика `src/domain` | Vitest, покрытие ≥ 90 % |
| Integration | модули с имитацией контекста ST и соседей | Vitest + happy-dom |
| **Снимки промпта** | итоговый промпт по ходам эталонного чата до и после правил Maestro: состав, порядок, размер | стенд, перехват запроса в имитации модели |
| Сценарии | прогон сценариев имитации: брак, листы, сбои фоновой модели | стенд |
| Производительность | добавочная задержка до отправки (P15) на ПК и в телефонном размере окна; размер файлов по чату | стенд |
| Две вкладки | ведущая вкладка, страж вкладок | стенд, две вкладки |
| Соседи | соседи после Maestro работают как без него (регрессия) | стенд |
| Ручная проверка | список в отчёте этапа + проверка на сервере после выкладки | ты и я |

## 5. Выпуски и выкладка на сервер

1. **Перед выкладкой:**
   - бэкап `settings.json`, лорбуков и пресетов на сервере;
   - **все вкладки ST закрыты** на ПК и телефоне (урок с откатами настроек);
   - твоё разрешение на выкладку.
2. **Установка:** клон репозитория в папку расширений сервера (или `git pull` при обновлении), без перезапуска ST, если не менялись серверные части. Затем мастер первого запуска.
3. **Проверка на сервере:** короткий список из отчёта этапа на реальном чате; снимок журнала ошибок.
4. **Откат:** выключить Maestro в панели расширений (хук `disable` вернёт штатное), при необходимости вернуть предыдущий тег; данные Maestro остаются в файлах `maestro-*`.
5. Детали сервера (пути, адреса) — только в твоих заметках, не в репозитории.
