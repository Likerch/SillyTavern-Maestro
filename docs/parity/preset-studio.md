# Паритет Пресет-студии (M34) с разделом Prompt Manager и пресетами Chat Completion SillyTavern

Источник списка функций — опись [`research/parity-preset.md`](../research/parity-preset.md) (SillyTavern 1.19.0), все 198 пунктов P-001…P-198 в её порядке. Состояние — этап 5, оболочка и интерфейс студии (`src/features/presetStudio/{module,studio,launcher,dialogs,strings,styles}.ts`, `view-*.ts`, `src/domain/preset-ui-*.ts`), 2026-10-04. Слой данных (`store.ts`, `st-preset.ts`, `versions.ts`), «Твой слой» (`layer*.ts`) и анализ (`analysis*.ts`) сведены в таблицу по их отчётам и тестам.

Статусы:

- ✅ — сделано в оболочке и проверено unit-тестами (`tests/features/presetStudio/{studio,launcher,view-*}.test.ts`, `tests/domain/preset-ui-*.test.ts`); вживую ещё не проверялось;
- ✅ + ⏳ store / layer / analysis — интерфейс готов и проверен, а сама работа с данными — в соответствующей части (её агент и тесты);
- ⏳ store / ⏳ layer / ⏳ analysis — пункт целиком в части другого агента; оболочка только показывает результат или ничего не делает;
- ✅ вживую — проверено на живом ST (ставит ведущий после проверки, см. «Проверить вживую» в конце);
- ❌ — не сделано, причина указана;
- N/A — к Пресет-студии не относится, причина указана.

«Замена» — настройка «Заменить раздел Prompt Manager Пресет-студией» (`replacePromptManager`, по умолчанию выключена: по плану M34 включается, когда таблица зелёная). Пока она выключена, Prompt Manager показывается как обычно, а студия открывается из пульта и командой `/maestro-preset`.

## Как устроено

- **Модуль** — `module.ts` (`createPresetStudioModule(factories)`, `presetStudioModule` из `index.ts`, ключ `presetStudio`, M34, этап 5, требует `st.oai.promptManager` и `st.presetManager`). Части строятся фабриками `createPresetStore(app, log)`, `createPresetLayer(app, log, store)`, `createPresetAnalysis(app, log, store)`; у каждой распознаются `install()` (его отписки — по одной или массивом — уходят в `own`), `dispose()` и ручка `api`; наружу выставляются `presetStore`, `presetLayer`, `presetAnalysis` и `presetStudio` (`{open(identifier?)}`). Если части нет, студия работает без неё (без слоя правки идут прямо в пресет, без анализа карта урезана), без слоя данных не открывается. Строки модуля — свои (`strings.ts`) плюс строки частей (`ANALYSIS_STRINGS`, `LAYER_STRINGS`, `PRESET_STORE_STRINGS`), чтобы они были до `install()`.
- **Замена раздела** — `launcher.ts`: `div#maestro-preset-launcher` вставляется перед `#completion_prompt_manager` в тот же `.range-block` (внутри `#openai_settings`, поэтому ST сам прячет его для Text Completion); раздел прячется только классом `body.maestro-pm-replaced` и стилем модуля — DOM, обработчики, окно правки и быстрые поля PM не трогаются, PM продолжает рендериться (P-007, P-012, P-013, P-131). Класс ставится, только пока сводка стоит на месте раздела. Сводка (имя пресета, включённые блоки, `promptManager.tokenUsage`, `promptManager.error`, значок несохранённого из `store.draft()`) обновляется по `CHAT_COMPLETION_PROMPT_READY`, `OAI_PRESET_CHANGED_AFTER`, `SETTINGS_UPDATED` и `store.onChange` с задержкой 250 мс. «Классический редактор» снимает класс до перезагрузки страницы. Выключение настройки, модуля или Maestro убирает сводку, класс и стиль.
- **Окно** — `studio.ts`: большой Popup ST (`<dialog>` в верхнем слое — выше `z-index` 3010 окна PM), на телефоне на весь экран; шапка (выбор пресета, «Не сохранено», ошибка сборки PM, режим правок, «Сохранить», «Сохранить базу», «Сохранить как», «Переименовать», «Импорт», «Экспорт», «Удалить», «Классический редактор»), вкладки «Карта», «Блоки», «Анализ», «Слой», «Версии», «Параметры» (клавиатура: стрелки по вкладкам, на телефоне — выпадающий список), редактор блока — боковая панель (на телефоне — поверх списка). Данные читаются заново при каждой перерисовке (`store.onChange`, `layer.onChange`), своей долгоживущей копии студия не держит (P-018). Фокус и курсор переживают перерисовку (`data-focus-key`), поле «Параметров» во время набора не перерисовывается.
- **Куда идут правки** — `EditRouter` в `studio.ts`. Если у текущей базы есть слой (или он заведён в этой сессии) и включено «Держать мои правки в моём слое» (`editsToLayer`, по умолчанию да), каждая правка записывается в слой (`layer.record`: правка текста с отпечатком базового текста `baseHash`/`baseText`, вкл/выкл, перемещение с якорем «после блока», свой блок с якорем, ключ тела) и сразу применяется к рабочей копии через хранилище. Блок, которого нет ни в сохранённой базе, ни в слое (сделан вне студии и не сохранён), в слой не записать — его правки идут только в рабочую копию. Без слоя правки идут в хранилище. «Сохранить базу» = `store.save()` (хранилище само вычитает слой из текущего пресета); «Сохранить» в режиме слоя: правки студии уже в слое, остальное (классический редактор, команды) — по выбору в слой (`migrateFrom` с предпросмотром) или в базу.
- **Чистые помощники** — `src/domain/preset-ui-blocks.ts` (виды блоков, права, строгие типы, поиск, подсветка, макросы с побочками), `preset-ui-order.ts` (перемещения, якоря слоя, порядок импорта списка), `preset-ui-io.ts` (импорт и экспорт списка промптов в формате PM), `preset-ui-diff.ts` («было/стало» с маской секретов), `preset-ui-params.ts` (ключи «Параметров», ключи подключения, стоп-строки).
