# Опись для паритета Лор-студии (M23): окно «Миры и лорбуки» ST 1.19 и Lore Library DES 2.6 (2026-10-04)

**Назначение.** Приёмочный список для таблицы паритета Лор-студии (M23, M35 в `docs/plan.md`). Каждая строка — одна функция штатного окна, которую Лор-студия должна повторить (или сознательно не повторять с причиной). Формат готов к переносу в `docs/PARITY.md` по образцу NAI Studio: «функция встроенного → аналог → статус». Всё сверено с кодом; номера строк — по указанным снимкам.

**Приоритет:** «обязательно» — без этого паритет не зелёный и кнопку перехватывать нельзя; «желательно» — удобство или редкий сценарий, можно отложить с пометкой.

**Сквозные правила реализации** (действуют для всех строк, дальше не повторяются):
1. **Сохранение книги.** Штатный `saveWorldInfo(name, data, immediately)` кладёт объект в `worldInfoCache` **по ссылке** (`WI:4183`) и сохраняет с общей на все книги задержкой 1 с (`WI:83`, `debounce_timeout.relaxed`). Отложенные сохранения двух разных книг в пределах секунды теряют первую на диске, а немедленное сохранение книги B отменяет ожидающее сохранение книги A (`cancelDebounce` в `_save`, `WI:4151-4161`). Лор-студии нужна своя очередь сохранений по книгам: всегда `immediately=true` (или своя задержка на книгу, затем `saveWorldInfo(..., true)`), после записи — `reloadWorldInfoEditor(name)` для классического окна и сброс кэша Lore Library DES (§9). Сохранённый объект больше не менять (взять новую копию через `loadWorldInfo`).
2. **Зеркало `originalData`.** У книг, импортированных из карточки, есть `data.originalData` (исходный `character_book`). Каждое изменение поля записи штатный редактор дублирует туда через `setWIOriginalDataValue(data, uid, путь, значение)` (`WI:2756-2766`). Пути — в `originalWIDataKeyMap` (`WI:2687-2724`) плюс ручные: `extensions.outlet_name` (`WI:3697`), `extensions.group` (`WI:3733`), `character_filter` (`WI:3160`, `3657`), `position` = `'before_char'`, если позиция 0, иначе `'after_char'` (`WI:3434`), и `extensions.<snake_case>` для чисел и трёхпозиционных списков (`WI:3237`, `3270`). Удаление записи — `deleteWIOriginalDataValue` (`WI:2774-2784`). На практике сервер при сохранении карточки перезаписывает `character_book` из `entries` (`SRV-CH:628-643`), но зеркало надо вести так же, иначе экспорт книги и сторонние расширения (Localizer зеркалит ключи: `SillyTavern-LorebookLocalizer/src/lorebook.js:17-22`) разойдутся.
3. **Незнакомые поля записей и книги сохраняются как есть:** сервер пишет тело запроса дословно (`SRV-WI:150-169`, только проверка наличия `entries`). Лор-студия не должна терять ни поля записей (`extensions`, поля других расширений), ни поля книги (`name`, `extensions`, `originalData`).
4. **Не трогать классический DOM без нужды, но держать его актуальным.** Слеш-команды и часть API читают DOM классического окна: `/world` ищет книгу среди `<option>` в `#world_info` (`getWIElement`, `WI:2090-2096`), `sortWorldInfoEntries` берёт порядок из `#world_info_sort_order` (`WI:2147`), Localizer определяет открытую книгу по `#world_editor_select` (`LorebookLocalizer/src/lorebook.js:5-9`). После создания, удаления, переименования и импорта книг вызывать `updateWorldInfoList()` (`WI:2061-2084`).

## 9. Lore Library DES 2.6: кампании, автопривязка, библиотека

**Владелец данных — DES (P3).** Лор-студия рисует интерфейс, а кампании, глобальные книги, журналы и автопривязку меняет только вызовами модулей DES. Пути ниже — от `SillyTavern-DES-RU\vendor\des\`; сокращения: `D/idx` = `index.js`, `D/tpl` = `template.html`, `D/api` = `src/systems/lorebook/lorebookAPI.js`, `D/cm` = `src/systems/lorebook/campaignManager.js`, `D/cp` = `src/systems/lorebook/campaignProfiles.js`, `D/al` = `src/systems/lorebook/autoLink.js`, `D/ui` = `src/systems/rendering/lorebook.js`, `D/mob` = `src/systems/rendering/lorebookMobile.js`, `D/modal` = `src/systems/ui/lorebookModal.js`, `D/ws` = `src/systems/ui/characterWorkshop.js`, `D/st` = `src/core/state.js`, `D/pers` = `src/core/persistence.js`.

**Как звать DES из Maestro.**
- Найти `<script src>` DES и импортировать модули `import(new URL('src/systems/lorebook/campaignManager.js', desScriptUrl).href)` — так получается **тот же экземпляр модуля**, что у DES (общие `wiDataCache`, очередь переключений `switchChain`, счётчик `switchesPending`). Образец — DES-RU: `SillyTavern-DES-RU/src/st.js:44-64`, `src/des-adapter.js:207-233`, `577-603`.
- Модули `lorebookAPI`, `campaignManager`, `campaignProfiles`, `autoLink` **не требуют** ленивого интерфейса DES и не имеют побочных эффектов при загрузке. Интерфейсные модули (`D/ui`, `D/mob`, `D/modal`) Maestro не вызывает.
- Звать **только после** `loadSettings()` DES (`D/idx:2833-2845`; например, после `APP_READY` и появления настроек DES): иначе внутренний `ensureLorebook()` + `saveSettings()` запишут умолчания поверх данных пользователя (`D/cm:44-66`).
- `state.extensionSettings` — `export let`, `loadSettings` заменяет объект `lorebook` целиком: читать `extensionSettings.lorebook` каждый раз заново, не кэшировать.
- Все мутаторы `campaignManager` сами сохраняют настройки DES (`persistence.saveSettings()`, который ещё и «банкует» версии персонажей активной кампании, `D/pers:549`). Событий о кампаниях DES **не шлёт**; косвенно приходят события ST: `WORLDINFO_SETTINGS_UPDATED` (при включении и выключении книг), `WORLDINFO_UPDATED` (при сохранении книг), `SETTINGS_UPDATED` (после отложенного сохранения настроек). Лор-студия перечитывает `extensionSettings.lorebook` после своих вызовов и по `SETTINGS_UPDATED`.

В таблицах раздела добавлен столбец «API DES для Maestro» — что звать, чтобы DES оставался владельцем.

### 9.9. Ловушки DES для Лор-студии

1. **Кэш DES** (`wiDataCache`, `D/api:40-58`) чистится только при открытии окна DES, при `deleteWorld`/`renameWorld` и обходится `loadWorldData(name, true)`. DES не слушает `WORLDINFO_UPDATED`. После каждой записи Лор-студии в книгу — `lorebookAPI.invalidateWICache(name)`, иначе открытое окно DES перезапишет файл старой копией целиком.
2. **Сохранения DES** — всегда вся книга, немедленно (`saveWorldInfo(…, true)`), что отменяет отложенное сохранение классического редактора по **любой** книге (`WI:4151-4161`); тексты — через 500 мс общим таймером модуля.
3. **Включение книг.** Каждое `activateWorld`/`deactivateWorld` дёргает `/api/settings/get` и пересобирает `#world_info`. Пакетировать `applyWorldActivation` и пускать через `queueBookTask`, чтобы не перемешаться с переключением кампании. **Никогда** не ждать внутри задачи очереди `setActiveCampaign`/`queueReconcile`/`deleteCampaign` активной кампании — взаимная блокировка (`D/cm:214-235`).
4. **Семантика кампаний:** неизвестный id снимает кампанию; журнал включает книги кампании, включённые вручную; следующая сверка снова включает книги кампании, выключенные вручную; журнал `autoLinked` защищает книги и после выключения автопривязки; переключение трогает 9 хранилищ персонажей, сохраняет дважды, может спросить `confirm()` в Workshop и закрывает лист персонажа; удаление активной кампании удаляет версии и файлы портретов.
5. **Переименование и удаление книг вне DES** (в окне ST, в Лор-студии) DES не замечает: старые имена остаются в кампаниях, глобальных и журналах, переименованная книга оказывается в Unfiled. Лор-студия обязана звать `onWorldRenamed`/`onWorldDeleted` сама (L-215, L-216).
6. **Перехват кнопки WI** (L-177). Порядок обработчиков на `#WI-SP-button .drawer-toggle`: ST `doNavbarIconClick` → DES `click.rpgLorebook` (возможно, дважды) → всё, что привязано позже, **не выполняется**, пока активен DES. Кроме снятия перехвата DES, Лор-студии надо погасить штатное открытие панели: (а) откатывать классы панели, как DES (с той же гонкой); (б) `$(el).off('click', doNavbarIconClick)` (функция экспортирована из `script.js`) и вернуть при отключении; (в) слушатель в фазе перехвата на `#WI-SP-button` — ловит только настоящие клики, а не `.trigger('click')` из `openWorldInfoEditor`, Escape, автооткрытия и импорта книги карточки. Глубокие ссылки ST на конкретную книгу (L-006) Лор-студия должна поддержать лучше DES: открыть именно эту книгу.

### 10.2. Трудные места для повторной реализации

1. **Сохранение и согласованность кэшей.** Общая на все книги задержка `saveWorldInfo`, отмена чужих отложенных сохранений, объект по ссылке в `worldInfoCache`, собственный объект классического редактора и собственный изменяемый кэш DES. Нужна одна очередь записей по книгам в Maestro: немедленная запись → `WORLDINFO_UPDATED` → `reloadWorldInfoEditor` → `invalidateWICache` DES; входящие `WORLDINFO_UPDATED` от CK, Localizer, слеш-команд и DES — перечитывание открытой книги без затирания несохранённого ввода (L-007, L-160…L-164, L-221, §9.9 п. 1–2).
2. **Глобальный выбор книг связан с DOM.** `selected_world_info` — `export let`, `/world` ищет книгу в `<option>`, `globalSelect` синхронизирует только обёртка WI, кампании и автопривязка DES тоже меняют выбор. Все переключения — через механизм «массив → `updateWorldInfoList` → `change` у `#world_info`» и очередь DES (L-020, L-145, L-203).
3. **Перехват кнопки при живом DES.** Три обработчика на одном элементе, `stopImmediatePropagation` DES, асинхронное открытие панели ST, программные `trigger('click')` и глубокие ссылки на книгу; всё обратимо при выключении Maestro (L-001, L-006, L-177, §9.9 п. 6).
4. **Переименование и удаление с переносом всех ссылок.** Функции ST не экспортированы; ссылки живут в карточках (через `merge-attributes` и подтверждение), в `charLore`, персонах, метаданных **только текущего** чата, кампаниях и журналах DES, Workshop, коллекциях Vector Storage и реестре Maestro; проверки занятого имени нет (L-024…L-027, L-215, L-216).
5. **Скрытая нормализация штатного редактора.** Раскрытие записи молча ставит `selective`/`useProbability`/`addMemo` в `true`, `probability` в 100, пустые числа в 0; показ списка дописывает шаблонные поля. Влияющее на движок (`selective`, `useProbability`) нужно воспроизвести или явно показать, иначе одна и та же книга сработает по-разному после открытия в разных окнах (L-080, L-081, L-104…L-106).
6. **Ввод ключей.** Разбор с запятыми внутри регулярок, два режима ввода, подсветка регулярок, подсказки ключей книги со счётчиком, автодополнение макросов, причуда снятия экранирования `\/`, кириллица при «целых словах» (L-063…L-066, L-070, L-084, L-085).
7. **Зеркало `originalData` и книга в карточке.** Карта путей с ручными исключениями, синхронизация в карточку только при сохранении персонажа, потери при обходе (`characterFilter`, `useGroupScoring: null → false`), удаление встроенной книги при снятии основной (сквозное правило 2, L-039, L-043…L-045).
8. **Привязки персонажа зависят от открытой формы.** `charUpdatePrimaryWorld` и импорт книги карточки работают только для персонажа в форме, а открытая форма при сохранении перезаписывает `#character_world` (L-039, L-043).
9. **Список: поиск, сортировки и страницы.** Точная настройка Fuse и автосортировка «Поиск», 14 сортировок с вторичным и третичным ключом, «Применить сортировку как Order» по всей книге в текущем порядке, `displayIndex` при перетаскивании только в пределах страницы (L-112, L-114…L-126).
10. **Позиция, роль и outlet в одном списке**, видимость глубины, `delayUntilRecursion` как `true`/`false`/число с причудой уровня 1, трёхпозиционные списки `null`/`true`/`false` (L-056, L-057, L-067…L-073, L-079).
11. **Фильтр персонажей.** Имена = файлы аватаров без расширения, теги = id, удаление поля при пустом выборе, чистка несуществующих имён при смене исключения (L-093, L-094).
12. **Импорт пяти форматов**, гонка «перезаписать» (удаление без ожидания) и несброшенный кэш; автоматическое включение импортированного у DES против ST (L-029…L-036, L-213).
13. **Кампании DES как режим.** Журналы `campaignActivated`/`autoLinked`, глобальные книги, подмена хранилищ Workshop, очередь и взаимные блокировки; показать пользователю «почему книга включена» и «что изменится при переключении» (L-195…L-197, L-205…L-207, §9.9 п. 3–5).
